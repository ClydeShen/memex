# 训练一个独立的路由器或打分器不算"训练"：第一性原则 3 只禁止改动认知模型的权重

第一性原则 3 规定"不训练模型"：凡是修改模型本身（微调、LoRA、任何权重更新）都算训练，一律不做；只调整模型外部的配置参数不算训练。调研多点、多级的快慢思考时发现（factory/records/research/adaptive-depth-2026-10-19.md），很多可用的方法属于第三种情况：它们不改 Reasoning 或 Intuition 的权重，而是另外训练一个**独立的小模型**，用来决定调用哪个组件、用多深的推理，或者给候选结果打分，例如 RouteLLM 的路由器、FrugalGPT 的打分器。原则 3 原来的界线没有覆盖这种情况。负责人确认：这不算训练（2026-10-19）。

## 决定

1. **认知模型**指 Memex 拿来做认知工作的现成模型：Reasoning 模型、Intuition 模型、Embedding 模型。原则 3 禁止的是改动这些模型的权重，这一点不变。
2. **独立的路由器或打分器**是另一个小模型，只负责以下两件事之一：
   - 决定把当前情况交给哪个组件，或者用多深的推理；
   - 给候选结果打分，决定接受、升级还是丢弃。
   训练这样的模型不算原则 3 所说的"训练"。
3. 训练和使用路由器或打分器时，必须满足：
   1. **标签只来自产品中也能拿到的信号**，主要是 Shadow Escalation 的结果，不能用 Oracle（与 ADR 0023 相同）。
   2. **它是一个可替换的 Provider**，通过配置接入（原则 6），可以换成启发式规则，或者完全不用。
   3. **可以复现**：训练数据、训练配置和产出的版本都写进 Experiment 快照。
   4. **成本单独计量**：训练和推理的成本单独记录，不混进 Reasoning 的指标。
4. 这条决定只是**允许**这类做法，不是采用。是否真的加入，仍然按原则 8 处理：先回答它解决了哪个已经测出来的问题，改进能不能测量。

## 考虑过的选项

- **算作训练，一律不做**：会排除一大类成熟的路由和级联方法。它们不改认知模型，和原则 3 想保护的东西（"同一个模型、变的是输入"）不冲突。
- **把认知模型的微调也放开**：会违反原则 3 的核心，也会破坏 ADR 0018"同一组对比使用同一个 Reasoning 模型"的前提。不采用。

## 后果

- VISION.md 第一性原则 3 补一句，说明独立的路由器或打分器不算训练，并引用本 ADR。
- 路由器或打分器只能使用产品里能拿到的信号来训练，所以它和 Calibration 一样，依赖 Shadow Escalation 的标签量。标签少的时候，启发式规则可能更好。
- 如果以后打算把某个打分器做成 Intuition 本身，需要重新判断：Intuition 模型属于认知模型，不能训练。
- 相关的候选方向记在 factory/design/open-questions.md（多级、多点的快慢思考）。
