# Research index

One line for each research file in this directory, with its conclusion. Open a file only when the conclusion is not enough. Most files are written in Chinese. The research files are not changed after they are written, so this index is where a new file gets its line.

- [adaptive-depth-2026-10-19.md](adaptive-depth-2026-10-19.md): How much to compute is itself a decision with several decision points, and depth is continuous and recursive; usable algorithms exist, but only those that need no training fit Memex (threshold cascades, adaptive stopping, rule-based metacognition, calibrated confidence).
- [as-built-docs-2026-10-13.md](as-built-docs-2026-10-13.md): As-built pages live in `factory/as-built/`, one page for each package, with `verified-at` and `covers` front matter. Generated content goes apart, and staleness is found mechanically from `git diff`.
- [async-stress-test-2026-10-14.md](async-stress-test-2026-10-14.md): A team that never talks can still work from the repository and the tracker if each state answers four questions: whose turn, how, when done, and who to ask when stuck; the useful parts go into the playbook.
- [code-factory-2026-10-27.md](code-factory-2026-10-27.md): The "software factory" has three generations and all keep the factory configuration apart from the product, which agrees with the three zones of ADR 0028; no one else isolates the two as strictly, and "dark factory" practices are not copied.
- [core-algorithms-2026-10-11.md](core-algorithms-2026-10-11.md): Recommended methods for the core functions: calibrated fast and slow routing, evidence-count confidence for Claims, budgeted context selection, executable Patterns, contradiction-driven revocation instead of time decay, gated ontology growth, and paired experiment statistics.
- [cross-check-2026-10-10.md](cross-check-2026-10-10.md): Earlier uncertain facts and core assumptions were checked against public sources; calibration alone is not enough for a decision model, and the same day it was corrected that trained open decision models and option probabilities from ordinary models avoid training.
- [factory-autonomy-2026-10-27.md](factory-autonomy-2026-10-27.md): Agents can run the factory with five layers of mechanical limits (permissions, check scripts, hooks, CI, review), hand-written summary numbers will drift, and Markdown versus structured files is decided by a rule given in the file.
- [feedback-loop-2026-10-14.md](feedback-loop-2026-10-14.md): Feedback is effective when the receiver acts on it; checks that can fail the work beat checks that only give opinions, conflicts need explicit routing, and reasoning-based review adds false-positive risk.
- [harness-playbook-validation-2026-10-17.md](harness-playbook-validation-2026-10-17.md): Third-party practice confirms the playbook's idea of a harness (guides and sensors, deterministic gates, minimal context files) and its loop cards, and names what is missing: review by sampling, comprehension debt and token cost as a signal.
- [harness2-2026-10-27.md](harness2-2026-10-27.md): Harness² does not overturn the concept or any ADR and is strong supporting evidence for improving without changing weights, but it raises four questions to answer: the unit of learning, self-modification, a comparison group, and cost.
- [language-toolchains-2026-10-13.md](language-toolchains-2026-10-13.md): A matrix of tools for Python and C# against the Node and TypeScript choices (versions, formatting, types, tests, boundaries, unused code, supply chain, one command for all); only part of the Python column was run.
- [llama-cpp-backend.md](llama-cpp-backend.md): Measured llama.cpp behavior: the server returns token probabilities and can turn thinking off, so the Intuition adapter works; output format guarantees were tested on build b11552.
- [pi-durable-2026-10-20.md](pi-durable-2026-10-20.md): Pi Durable is very close to ADR 0005 and ADR 0024 in design, but is not a foundation now (it has its own store, and it is experimental); borrow the design, add no dependency, and judge an adapter after the validation stage.
- [playbook-review-2026-10-14.md](playbook-review-2026-10-14.md): A two-round review of the playbook found conflicts, loop gaps and ambiguities, then set new file boundaries so that each rule lives in one file.
- [qa-harness-tools-2026-10-14.md](qa-harness-tools-2026-10-14.md): A survey of QA tools for agent-driven projects in 11 categories (browser tests, test generation, mutation, test selection, flaky tests, hermetic integration, contract tests, visual regression and more), with advice for this repository and for projects in general.
- [review-2026-10-10.md](review-2026-10-10.md): The first review of the design documents fixed contradictions between them and unified ambiguous terms with industry terms; a few points were left for the user to confirm.
- [shared-vs-personal-harness-2026-10-14.md](shared-vs-personal-harness-2026-10-14.md): Shared and personal harness are kept in separate layers, shared content does not depend on a person's environment, and only the result is checked, not the process; these are written as team conventions.
- [standards-and-config.md](standards-and-config.md): Reusable data standards for ADR 0007 and configuration practices for ADR 0008: `{type, config}` components, declare then wire, model aliases, composition and override, versioned configuration, validation at load, and trusted configuration only.
- [system3-divergent-2026-10-19.md](system3-divergent-2026-10-19.md): An offline process that generates, filters outside and keeps useful abstractions has support in sleep, dreaming and incubation research and in algorithms such as DreamCoder and FunSearch, and most of it fits Memex without training.
- [workflow-closure-2026-10-14.md](workflow-closure-2026-10-14.md): A stress test of the planner, coding and review loops found gaps; the concepts of graph and loop engineering give a checkable definition of a closed workflow, plus state machines, kanban policies, examples as specification, and review rules.
