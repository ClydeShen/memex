# 文档审阅与概念统一（2026-10-10）

审阅范围包括 VISION.md、GLOSSARY.md、ADR 0001–0015、factory/design/dependencies.md 和 factory/design/open-questions.md。目标有两个：找出文档之间的矛盾和含糊的概念，并把含糊的概念与业界标准术语对齐。所有修改已直接写入各文件，本文件记录改了什么、为什么改。

## 一、文档之间的矛盾（已修正）

| # | 问题 | 修正 |
|---|---|---|
| 1 | 术语表开头写着"运行在本地的认知运行时……结合本地模型"，与 ADR 0001（架构不绑定模型）、0013（可在各平台部署）以及 Framework / Instance 的定义矛盾 | 改为"认知 Agent 的 Framework"，并说明它与 Instance 的关系 |
| 2 | 术语表中 Baseline 写着"同一个本地模型"，没有 B3，也没有 ADR 0010 新增的"去掉 Intuition"变体 | 补充 B3 和 B3-noI；标明 MVP 只用 B0、B1、B3、B3-noI；B-sym 只用来检查难度 |
| 3 | ADR 0007 把"Trace"整体归到 OpenTelemetry，而 ADR 0015 规定认知 Trace 是数据，写入事件日志 | ADR 0007 拆成"认知 Trace"和"运维遥测"两行；术语表注明运维日志不叫 Trace |
| 4 | VISION 原则 8 要求"任何东西引入前都要有实验证据"，但部署、权限、可观测性（ADR 0013–0015）并没有、也不需要实验 | 原则 8 只适用于认知组件和本体，工程基础设施按工程需求决定 |
| 5 | ADR 0001"选型只看免费"与 ADR 0013"分发的组件必须允许再分发"之间没有互相引用 | ADR 0001 增加一条补充，指向 ADR 0013 |
| 6 | 讨论 jj 时约定的两个"预留口子"（事件带前一条事件的标识、矛盾的 Claim 可以共存），以及"事件带 Instance 标识"，在关闭待决问题时一并丢失了 | 写入 ADR 0005 和 ADR 0002 |
| 7 | ADR 0014 说"所有改动都经过 Action"，但没有说明 Observation 写入事件日志算不算 Action | 明确规定：Observation 是记录，不是 Action；根据 Observation 形成 Claim 才是 Action |
| 8 | 里程碑划分（M0/M1/M2）仍列在"等待确认"中，却已被 ADR 0010、0012、0013 和依赖表引用 | 在 open-questions 中标注出来，**需要你正式确认** |
| 9 | VISION 核心模块表写着"Experience 日志"，但 ADR 0005 中的基础是"事件日志"，Experience 只是从事件日志推导出来的 | 统一为 Event Log，Experience 和 Trace 都是它的 Projection；表中补充 Action 模型、Policy、运维遥测 |

## 二、含糊或一词多义的概念（已统一）

| 原来的说法 | 问题 | 统一后的术语 |
|---|---|---|
| "Provider" | 同时用来指 Memex 的组件（Intuition Provider）、模型服务商（"云端 Provider"）和推理后端（"Model Provider"） | **Provider** 只指实现 Cognitive Contract 的组件；推理后端统一叫 **Model Backend**；公司统一叫"模型服务商" |
| "认知状态" | ADR 0002 用它表示 Epistemic Status，但 Cognitive State 的中文也是"认知状态" | Epistemic Status 的中文统一为"**确信状态**"，并新增"有争议"一档 |
| "置信度" | 同时指 Claim 的置信度和 Intuition 输出的把握程度 | Claim 的叫 **Confidence**（置信度）；Intuition 的叫 **Certainty**（把握度）；Calibration 只作用于 Certainty |
| "时间" | 模拟器时间、系统时钟、validFrom、observedAt 混在一起使用 | 采用数据库领域标准的双时态：**Valid Time**（何时在世界中为真）和 **Recorded Time**（Agent 何时得知）；延迟指标另用系统时钟 |
| "领域"与"World" | World 0 叫"World"，实际上指的是一个领域 | 新增 **Domain**（主题领域）和 **Environment**（Agent 与 World 交互的接口）。World 0 作为名字保留，指"以 Memex 为 Domain 的那个 World" |
| "组合根"、"适配器" | 只是随口使用，没有定义 | 与标准术语对齐：**Composition Root**；Cognitive Contract 是端口，Provider 是适配器（Ports and Adapters） |
| "事件日志派生的视图" | 没有标准名称 | 采用 Event Sourcing 的标准术语：**Event Log** 和 **Projection**；快照只是用来加速重放 |
| "在最后负责任的时刻" | 没有注明出处 | 注明出自 Lean 软件开发（Poppendieck）：拖过这个时刻还不决定，就会失去一个重要的选项 |

## 三、第三方验证

| 概念 | 结论 | 依据 |
|---|---|---|
| 以事件日志为事实来源，视图可以丢弃重建，快照只是优化手段 | 确认，就是标准的 Event Sourcing | 多个二手来源说法一致；概念最早由 Fowler 系统阐述 |
| 双时态：valid time 与 transaction time | 确认。SQL:2011 中分别对应 application-time period table 和 system-versioned table | 亚利桑那大学 TSQL 资料、SQL:2011 时态特性论文 |
| OpenTelemetry 日志数据模型的字段名 | 确认：Timestamp、ObservedTimestamp、SeverityText、SeverityNumber、Body、Attributes、Resource、TraceId、SpanId。已写入 ADR 0015 | opentelemetry.io 官方规范 |
| Composition Root 与端口和适配器 | 确认：核心持有端口，适配器实现端口，Composition Root 在启动时把两者接起来。Seemann 本人对 Composition Root 的原始定义，这次没有检索到 | Cockburn（2005）、arc42 |
| JSONL 和 NDJSON | 实际上是同一种格式：UTF-8 编码，每行一个 JSON 值。两者都没有 RFC，只有社区规范（jsonlines.org、ndjson-spec）。注意它不同于 `application/json-seq` | jsonlint、W3C JSON-LD 邮件列表 |
| 最后负责任的时刻 | 确认出自 Poppendieck 的《Lean Software Development》（2003），更早源于 Lean Construction | Coding Horror、Wirfs-Brock |
| llama.cpp 输出的不确定性 | 已由官方 README 和 Issue #7052 确认（见 cross-check-2026-10-10.md），ADR 0005 已把"未找到资料"改为确认后的结论 | 同左 |
