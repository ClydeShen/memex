# 每个里程碑契约先行：先设计接缝和关卡，先打通最薄的端到端，再并行实现各组件

roadmap 定下了里程碑，但没有细到可以执行、可以追踪的任务。Memex 的组件按依赖倒置（ADR 0008）互相连接：上游的输出就是下游的输入。如果各组件各做各的、最后才接起来，接缝上的设计问题要到最后才暴露（用户和协作者确认，2026-10-13）。

## 决定

每个里程碑都按下面的流程推进：

1. **集成设计**：列出这个里程碑涉及的组件；画出接缝，标明谁产出、交付什么 schema、谁消费；规定每条接缝的关卡；把工作拆成可以追踪的 story。产出一份里程碑集成设计文档，放在 `docs/plans/`，经用户审阅后开工。
2. **最薄的端到端**：用最薄的方式把整条路径打通一次，例如 V0 中"一个房间、一步达成目标"的 Micro World。目的是在纸面设计之后、各组件加厚之前，尽早发现接缝设计的漏洞。
3. **契约先行**：把接缝的 schema 和端口写进 `@memex/contracts`，并为每个端口写一套**一致性测试**（Conformance Suite）：实现这个端口的组件都必须通过。
4. **组件并行实现**：每个组件只依赖契约，接缝另一边用 Fake 顶替，按这个组件自己的最佳实践实现。
5. **集成关卡**：把组件真正接起来，运行端到端测试和里程碑的通过标准，通过后合并。

关卡分三层：

| 层次 | 位置 | 检查什么 |
|---|---|---|
| schema 关卡 | 接缝 | schema 接受合法输入、拒绝非法输入；导出的 JSON Schema 能校验示例 |
| 一致性关卡 | 组件 | 组件通过它所实现端口的一致性测试 |
| 集成关卡 | 里程碑 | 端到端测试和里程碑的通过标准 |

## Considered Options

- **按层依次实现**（原 roadmap 中 V0.1–V0.6 的顺序）：通过标准到最后一步才第一次被检验。被否决。
- **只做最薄的端到端，然后边做边加厚，不先设计接缝**：接缝会随实现漂移，组件之间难以并行。被否决。

## Consequences

- 每个里程碑的第一项工作是写集成设计文档；V0 的是 `docs/plans/v0-integration.md`。
- roadmap 第四部分的 V0 任务分解，改为指向这份文档。
- 约束新增 P6。
- 契约在里程碑之间仍可以修改，到决策关卡才冻结（ADR 0012、0020）。
