# 实验矩阵保持最小，实验服务于把系统搭起来，而不是做对比研究

Memex 是研究性质的开发。实验的目的是用几组快速对比，引导架构尽快成形，成为一个可用的系统，而不是全面比较各种方案。所以每个维度只保留一个主选，最多一个对照，并且事先定好收敛规则。

| 维度 | 主选 | 对照（同时运行，见 ADR 0018） |
|---|---|---|
| Intuition | Tev1 4B | 启发式规则（底线） |
| Reasoning | Qwen3.5-9B，固定（**已由 ADR 0017 修订**：主选 Qwen3.8-27B，备选 Qwen3.6-35B-A3B） | 无 |
| 知识存储 | Oxigraph | 无 |
| 向量模型 | 一个嵌入模型，B1 和距离判断共用（ADR 0017：EmbeddingGemma-2） | 无 |
| Cognitive Strategy | 快慢双系统 | 无 |
| Baseline | B0、B1、B3 | B3-noI（B3 去掉 Intuition，全部走 Reasoning） |

MVP 阶段只回答三个问题：
- **Q1**：Intuition 能不能在不降低准确率的前提下减少推理调用？用 T2 测，比较 B3 和 B3-noI。
- **Q2**：Claim 加溯源，是否比 RAG 更能抵抗错误或过时的信息？用 T4 测，比较 B3 和 B1。
- **Q3**：积累经验后，推理调用会不会持续下降？用 T6（长序列学习）测，看 B3 的学习曲线（ADR 0018：原文写的是 T5，T5 是经验迁移，MVP 不测）。

所有任务都设计成目标型任务，Q1–Q3 中的"准确率"指目标完成率（ADR 0021）。

B-sym 只用来检查题目难度。T0、T1、T3 以及跨领域迁移，等上面三个问题有了答案再加入。

## 收敛规则

- **Intuition**：如果 Tev1 不如启发式规则，就换成"读取 Qwen 的选项概率"，只换这一次；如果还是不如，就暂时直接用启发式规则，继续往前推进。
- **Oxigraph**：在 10 万条 Claim 的规模下，如果明显变慢，就换掉；如果没有问题，就不再讨论。
- **其他维度**：没有出现明确的失败，就不增加对照。新组件只在某个关键问题被它卡住时才引入。

## Consequences

- 模型运行在哪个 Model Backend 上，只是配置选择，不是硬依赖（ADR 0008）。作者目前在本机使用 llama.cpp，换成 vLLM、其他兼容 OpenAI 接口的服务或远程端点，都只需要改配置。Ollama 的 `/v1/systemone` 不作为前提，因此需要写一个很薄的 IntuitionProvider 适配器：
  - 对外使用"状态 + 选择题"格式（ADR 0018：只有选择题一种题型，与 Tev1 模型卡的输入格式一致）。
  - 对内把每道题转成 Tev1 的格式：系统提示、带字母编号的选项，关闭思考模式，temperature 设为 0。
  - 通过后端返回的 token 概率（logprobs），读出每个选项字母的概率。是非题是两个选项的选择题；打分题是选项有顺序的选择题，取各选项概率的加权期望。
- 这个适配器要求后端能返回 token 概率，这是它对后端唯一的能力要求；不提供 token 概率的后端（例如部分云端 API），无法通过它来提供 Intuition。
- 同一个适配器换成 Qwen 模型，就是收敛规则中的那个备选方案，不需要另写代码。
- 被暂缓的 Kev、Nimble、Laya、jevos 都兼容同样的接口格式，以后需要时可以低成本加回来。
