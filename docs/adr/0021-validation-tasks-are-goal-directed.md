# 验证任务一律设计成目标型，目标完成率是所有对比的共同指标

产品定义是"给它一个目标，让它自己去完成"（VISION）。但验证阶段的三个问题测的都不是这一点：Q1 测是否节省推理调用，Q2 测能否抵抗错误或过时的信息，Q3 测是否越用越省。GLOSSARY 中的 T3"目标导向行动"又被 ADR 0010 推迟。这样可能出现 Q1–Q3 都回答"是"、但"完成目标"这一核心能力从未被验证的情况。

## 决定

1. **不新增实验问题**（ADR 0010 的实验矩阵保持最小）。Q1、Q2、Q3 和它们使用的 Task Class（T2、T4、T6）不变。
2. **T2、T4、T6 的任务都设计成目标型**：每道题给 Agent 一个 Goal，Agent 需要在 Micro World 中通过一系列 Action 达成它，由 Environment 返回的 Observation 判断目标是否达成。
   - T2（诊断）：目标是找出并处理故障的原因。
   - T4（信念修正）：目标的达成依赖于正确识别错误或过时的信息。
   - T6（长序列学习）：同一 Task Family 的目标按顺序给出。
3. **目标完成率是所有对比的共同主指标**，由 Evaluator 根据 Ground Truth 判定，不回流给 Agent（ADR 0018）。
   - Q1–Q3 中所说的"准确率"，一律指目标完成率。例如 Q1 的非劣效检验，比较的是 B3 与 B3-noI 的目标完成率。
   - 单步决策的正确率只作为诊断指标，用来定位问题。
4. 成本指标（ADR 0018）照常记录。"每个达成的目标所用的推理调用和 token"是 Q1、Q3 的主要成本口径。

## Consequences

- World Generator 生成的每道题都要包含 Goal、可用的 Action，以及判断目标达成的条件。这一点在 V2 实现真实的 World Generator 时落实；V0 的最小 Micro World 也按这个形式设计，只是规模更小。
- B-sym（掌握完整规则的符号求解器）用于检查目标型任务的难度：如果 B-sym 和 B0 都能轻松达成，就说明题目太简单（天花板效应，ADR 0017）。
- 产品阶段 P1 的设计以"目标"为中心：如何下达目标、如何查看进度、哪些行动需要用户批准（open-questions.md 第 4 条）。
