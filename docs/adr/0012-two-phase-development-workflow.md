# 开发分两个阶段：先轻量实验，定型后再走正式流程

`main` 是新系统唯一的基线。旧的 `master` 保持原样，不再处理；旧代码已归档在 `archive/memex-v1`。

**实验阶段**（从现在起，到架构和标准定型为止）：
- 从 `main` 开分支或 worktree，在本地快速验证、整合，每个实验或模块一个分支。
- 分支要通过事先写好、可以观察的通过标准，之后才用普通 merge 合并进 `main`，不开 PR。
- 没通过的分支保留下来作为记录，不合并。

**正式阶段**（ADR 0010 的 Q1–Q3 都已有答案，并且 Cognitive Contract 冻结为 v1 之后）：每次改动都走 PR、跑 CI，必要时补写 ADR。

这样分开，是为了让架构尽快成形，避免过早引入流程负担；同时，合并进 `main` 的内容始终是验证过的。
