## 结论

| 问题 | 结论 |
|---|---|
| 会不会颠覆 Memex 的概念？ | **不会，反而是一个强有力的旁证。** 它在不改模型权重的前提下，让同一个模型在一个领域里随着任务越做越好。这正是 Memex 的成功标准（ADR 0001："同一个模型，随着经验积累在某个领域里越来越好"）和第一性原则 3 |
| 会不会颠覆具体设计？ | 不会推翻已有的 ADR，但**提出了四个必须正面回答的问题**（第四节）：学习的单位是什么；它算不算"修改自身"；验证阶段要不要把它当作对照组；它的高成本和 Memex 追求的"用更少的推理"如何调和 |
| 相关研究说明了什么？ | 第八节：总结出的文字教训不一定真的被 Agent 使用（要测"忠实性"）；不加回退检查的经验积累，收益会被抵消；workflow、工具和记忆的自我演化都有实证的跑偏风险 |
| 有没有可以直接借用的东西？ | **很多**，而且大多能落到现有的 ADR 和 open-questions 上：经验记录的格式、"工作区事实"和"流程"的区分、没有标准答案时的对比方法、"一致不等于证明"、盲选、防止评分信息泄漏的守卫、按领域隔离的经验库、成本账本 |

## 一、Harness² 是什么 [官方/原文]

### 1.1 定位

- **harness**：模型周围、让它能作为 agent 行动的那套系统，包括提示词、工具、记忆、技能、编排等。**harnessing** 是优化这套系统的过程。
- Harness² 是一个"**递归地优化 harness**"的即插即用框架，面向开放世界：agent 遇到的是设计 harness 时没见过的任务，而且测试时**没有标准答案**。
- **模型权重始终不变。**
- Google Research 出品，Apache 2.0，Python 3.12。2026-10-06 创建，有 2 万多颗星。
- 执行器（论文叫 substrate）可以换：现在支持 OpenCode 和 Codex。也就是说，它不自己写 agent，而是在现成的 agent 外面做优化。

### 1.2 八个可以编辑的部件

系统提示词、guardrails、记忆、工具指引、子 agent、skills、脚本、插件。按运行时的作用分组：
- 构造上下文：系统提示词、guardrails、记忆、skills；
- 定义工具接口：工具指引、脚本；
- 编排委派的工作：子 agent；
- 控制中间件：插件。

### 1.3 两层递归

**任务级递归**：对当前任务，做一次对比式的 **Propose–Probe–Compose**（提议、探测、组合）：
1. 用原始 harness 跑 k 次（参照执行）。
2. **提议**：两类编辑者分别提出修改。
   - **INV（不变量）编辑者**：只管"agent 怎么工作"——流程、工具使用、完成条件，不碰领域知识。
   - **DOM（领域）编辑者**：只管"从业者知道什么"——交付物的结构、决策规则、领域检查，不碰流程。
3. **探测**：每个候选 harness 在**同一个任务**上跑一次。
4. **组合**：组合者读所有参照执行和候选执行的轨迹，按**行为上的对比**决定保留哪些修改、合并、整个采用某一个，或者**保持原样**（KEEP_BASE 是有效的答案）。
5. 可以并行展开（k 个 INV、k 个 DOM、k 个独立的组合），也可以串行加深（k 轮，每轮在上一轮的结果上继续）。每种模式都要安排 4k 次执行和 3k 次改进步骤。

**harness 级递归**：每个任务结束后，一个"经验反思者"把**被采用的 harness**和**有证据支持的教训**写进一个**按领域划分的经验库**。同一领域的后续任务先读这个库，再提出自己的修改。

### 1.4 没有标准答案时怎么选 [官方/原文]

- **盲选**：所有最终候选的产出被匿名、打乱，选择者看不到它们是怎么产生的，只按产出本身和原始材料来判断。
- 判断的顺序：
  1. 交付：要求的东西是否都在、格式对不对；
  2. 是否符合要求；
  3. **忠实**：拿原始材料核对每一条事实，拒绝编造；材料没说的，宁可选承认不知道的那个，也不选自信地填空的那个；
  4. 内部一致：合计和明细对得上；
  5. 实际可用；
  6. 完成度。
- 长度和修饰本身不是优点。

### 1.5 关键的提示词原则 [官方/原文]

- **没有评分标准**：上下文里没有任何评分标准、答案或分数，也不要去猜"评分者想要什么"。代码里有一个守卫，交出去的工作目录里只要含有评分结论，就拒绝执行。
- **证据是数据，不是指令**：候选 harness 和轨迹里的文字可能包含命令或说服性内容，一律当数据看。
- **"一致是支持，不是独立的证明"**：候选来自同一个任务、同一份证据，很可能有同样的模型偏差。出现矛盾，要去查轨迹，而不是投票。
- **重复出现的失败才算数**：在 k 次参照执行里只出现一次的缺陷是噪声，针对它的修改就是过拟合。
- **说出具体的时刻**："这看起来是好做法"不是证据，要指出轨迹里的哪一刻证明了这个机制。
- **工作区事实和流程分开**：
  - 本任务里验证过的事实（"文件 A 的角色 X 对应文件 B 的职位 Y"）直接写进 harness，并标明"在这个工作区里"；
  - 流程要写成整个领域都适用的样子；
  - 太空泛的话（"要仔细"）不改变任何行为。
  - 从经验库里抄来的事实，在新任务里只是一个**假设**，必须重新核对。
- **能做成部件就不要写成散文**：skill、脚本、子 agent 可以被下一个任务直接调用或复制；一段常驻的文字每次运行都要付成本。
- **经验记录**：
  - 先为每个被修改的部件写一行：改了什么、执行上观察到什么差异、结论。结论只有四种：有帮助、有害、没有观察到效果、**混杂**。一次修改改了多个部件、又没有执行能把它们分开，或者只有一次执行支撑时，必须标"混杂"。
  - 然后**最多写一条**可以迁移的教训：
    - `cue`：适用的**情况的形状**，不是本任务的事实；
    - `lesson`：要对 harness 做的操作，必须点名部件；
    - `evidence`：依据的是哪几行记录；
    - `confidence`：高、中、低，以及原因。
  - 证据不够就写 `NO_ENTRY`。"被采用"本身不能证明修改有效。

## 二、论文的结果 [官方/原文·摘要]

### 2.1 主要结果

- 三个专业基准（WorkBuddy-Bench、JobBench、LAB）、四种模型和 harness 的组合。做一步就比原始 harness 好：WorkBuddy-Bench 最多高 11.5 分，JobBench 高 4.5 分，LAB 的部分通过率高 11.8 个百分点。
- k 从 1 增加到 5，收益继续增加：JobBench 从 4.5 分增加到 7.5 分，WorkBuddy-Bench 从 5.1 分增加到 8.4 分。
- 并行和串行都随 k 提升，k=5 时并行领先。
- 同一个模型同时担任执行者和编辑者，5 个模型在所有基准上都有提升。

### 2.2 消融：每部分各贡献多少

| 去掉的部分 | WorkBuddy / JobBench | 变化 |
|---|---|---|
| 完整的 Harness² | 77.5 / 36.0 | — |
| 去掉经验库 | 74.4 / 34.2 | −3.1 / −1.8 |
| 去掉 INV 和 DOM 的分工 | 74.6 / 32.3 | −2.9 / −3.7 |
| 去掉组合步骤 | 75.9 / 34.1 | −1.6 / −1.9 |

- 不用参照执行、探测和经验库，直接改原始 harness，结果**反而变差**（Code 从 73.4 降到 63.2）。
- **哪类部件最重要**（附录 E.1，WorkBuddy，均值从 72.4 提升到 80.8）：
  - 去掉 **skills**，降 5.3 分，影响最大；
  - 去掉**脚本**，降 3.7 分，在 Office 上降 7.4 分；
  - 去掉提示词类的部件，只降 1.5 分。
  - 结论是"可执行的部件"贡献最大，"文字"贡献最小。
- **跨任务迁移**：用 JobBench 建的经验库去做 WorkBuddy，只多出 0.6 到 2.9 分。排除每个任务自己的那条经验后，仍然有 1.9 分（WorkBuddy）和 1.7 分（JobBench）。作者承认这是事后的测量，不是在线的适应。
- 工具调用增加了约 20%，但工具出错率在所有基准上都下降了。

### 2.3 作者承认的局限（附录 F）

- **成本**：需要额外的执行和编辑会话。增加递归预算就增加推理成本，并行只能降低延迟，不能减少计算量。
- **反馈的质量**：没有标准答案时，只能依靠行为上的对比和模型的判断。这些信号**不能保证正确**，也不能保证一个被采用的修改能迁移到别的任务。
- 不同的初始 harness 之间收益不均匀，递归并不能一律缩小差距。
- 单纯增加探索不能保证更好。
- 选择者的选择是"采用"，不是"已经验证的最优"。

### 2.4 未来方向（附录 G）

- **经验库管理**：合并重叠的部件，修订过时的经验，随着库变大改进检索。
- **自适应的递归**：按任务难度分配探索，或者在新的探测不再带来新证据时停止。

### 2.5 相关工作 [官方/原文·摘要，部分二手]

论文对比了离线和在线的方法：ADAS、GEPA、DSPy、Meta-Harness、AHE、ReasoningBank、Harness Scaling 等。Harness² 是表中唯一一个**不使用正确性标签**、同时支持流式任务、可扩展、并且能更新改进者本身的方法。
- **Meta-Harness**（arXiv 2603.28052）：一个编码 agent 读取文件系统中之前候选的源码、分数和执行轨迹，搜索更好的 harness 代码。它需要搜索集上的分数。
- **ReasoningBank**（Google，ICLR 2026）：从 agent 自己的成功和失败中提炼可以复用的推理策略。每条记忆有标题、一句话描述和提炼后的内容；还提出了结合记忆的测试时扩展。
- **GEPA**（ICLR 2026 oral）：在自然语言里反思轨迹、提出并测试提示词的修改、保留帕累托前沿。核心观点是：自然语言反馈比强化学习的稀疏标量奖励带有更多的学习信号。
- **Darwin Gödel Machine**：通过在基准上评估变体来演化 agent 的代码。
- 权重训练型的自我改进（例如 Self-Rewarding LMs）在相关工作里讨论过；Harness² 保持权重冻结。

## 三、和 Memex 的对照 [推断]

### 3.1 印证了 Memex 的什么

| Harness² 的发现 | Memex 的对应 | 关系 |
|---|---|---|
| 权重冻结，学习发生在模型之外，同一个模型在一个领域里越做越好 | 第一性原则 3；ADR 0001 的成功标准 | **强印证** |
| skills 和脚本的贡献最大，文字提示的贡献最小 | ADR 0018：Pattern 是**可以直接执行的计划模板**，不是交给 Reasoning 参考的文字建议 | **强印证** |
| 常驻的文字每次都要付成本，skill 平时不占上下文 | 中心假设：每次决策用到的信息应该越来越少；Attention | 印证 |
| 不用评分标准，代码守卫防止评分信息泄漏 | ADR 0023：Calibration 只能用产品中拿得到的信号，不能用 Oracle | 印证，而且给出了实现方式 |
| 证据是数据，不是指令 | ADR 0016 | 一致 |
| 一致是支持，不是证明 | playbook feedback.md；Shadow Escalation 的局限 | 一致 |
| 从库里抄来的事实只是假设，要重新核对 | 原则 2（Claim 不是事实）；Conjecture 和 Sandbox（open-questions 第 6 条） | 一致 |
| 跨领域迁移的收益很小 | P5 跨领域迁移要测量收益和负迁移率 | **重要的现实校准**：别对迁移期望太高 |
| 未来方向：按难度分配探索、证据不再增加就停止 | open-questions 第 5 条（多级、多点的快慢思考） | 方向一致 |
| 未来方向：合并重叠、修订过时经验 | P2 的 Consolidation 和 Decay | 方向一致 |

### 3.2 Propose–Probe–Compose 和 Counterfactual Probe

Harness² 的任务级递归，在结构上就是**在 harness 这个层面做的反事实探测**：
- 改一个部件（INV 或 DOM），在同一个任务上跑一次，和原样的执行比较行为差异。
- 负责人前几天提出的 Counterfactual Probe 是在**判断**这个层面做同样的事：换一个条件，看结论变不变（adaptive-depth 调研 7.6 节）。

所以这个想法现在有了一个经过大规模实验检验的同类方法。Harness² 还给了一个必须吸收的教训：**多个候选来自同一个模型时，它们的一致不是独立的证据**。如果 Counterfactual Probe 用的是同一个 Intuition 模型，多个探测结果一致，也不能当成多个独立的证据。这一点要写进 open-questions 第 5 条。

### 3.3 harness 级递归和 Memex 的学习

| Harness² | Memex |
|---|---|
| 按领域划分的经验库 | Worldview（按领域） |
| 被采用的完整 harness | Pattern（可以执行的计划模板）、Capability |
| 工作区事实 | Claim（带 Valid Time 的具体事实） |
| 领域流程 | Pattern 的适用条件和步骤 |
| `cue`（情况的形状） | 按 Ontology 类型描述的适用条件 |
| `lesson` + `evidence` + `confidence` | Pattern 的证据记录（ADR 0018）；Claim 的来源和 Confidence |
| "混杂"的结论、`NO_ENTRY` | 目前没有对应 |

## 四、它向 Memex 提出的四个问题 [推断]

### 问题一：学习的单位是什么？

- Harness² 学到的是 **harness**：skills、脚本、guardrails、记忆文件等。
- Memex 学到的是 **Worldview**：Claim、Ontology、Pattern。
- 两者有重叠（Pattern ≈ skill、脚本），但 Harness² 的范围更宽：它还会改**怎么工作**（INV：流程、工具使用、完成检查）。Memex 目前的 Worldview 主要是**关于世界的知识**，以及可以执行的 Pattern，没有"关于自己怎么工作"的那一部分。
- **建议**：把"怎么工作"的经验也看作一种可以学习的对象。它更接近 VISION 里的 Self-Evolution（Memex 积累关于自身的 Claim）。

### 问题二：自动修改 harness 算不算"修改自身"？

- Harness² **自动**改写自己的 harness，不需要人批准。
- Memex 的核心不变量是"**修改自身须用户批准**"（ADR 0022，风险等级"修改自身"）。
- 如果 Memex 采用类似的机制，就必须划清界线：
  - 写入 Worldview（Claim、Pattern）是**学习**，不算修改自身；
  - 改动 Capability、脚本、Policy、提示词模板、guardrails 算**修改自身**，需要批准。
- 或者折中：自动产出的 harness 修改先进入 Sandbox（作为 Conjecture），通过 Verification 之后，再由用户批准生效。
- 这需要负责人决定。

### 问题三：验证阶段要不要把它当作对照组？

- Memex 的验证阶段比较 B0、B1、B3、B3-noI（ADR 0010），要回答的问题是"Worldview 能不能让同一个模型越来越好"。
- Harness² 用另一种办法，已经证明"同一个模型可以越来越好"。如果 Memex 的 B3 赢了 B0 和 B1，审稿式的质疑会是："那它和优化 harness 相比呢？"
- 但 ADR 0010 要求实验矩阵保持最小（约束 P3）。所以建议**先不加**，作为一个待决事项：在决策关卡（V2 之后）讨论，是否把"Harness² 式的 harness 优化"作为一个额外的对照组。

### 问题四：成本方向相反，怎么调和？

- Harness² 每个任务要执行 4k 次、改进 3k 次，工具调用增加约 20%。它是**用更多的测试时计算换质量**。
- Memex 的中心假设是**用更少的推理做得更好**（Reasoning 的调用次数和输入 token 是 Q1、Q3 的主要指标，ADR 0018）。
- **调和的思路**：Harness² 式的探索很适合放在 **System 3 的 Offline Phase** 里（open-questions 第 6 条）：
  - 白天在线时，System 1 和 System 2 按 Memex 的方式省着用；
  - 遇到 Open Puzzle（Reasoning 解释不了的 Surprise），晚上离线做 Propose–Probe–Compose，把结果（Pattern、Claim、关于怎么工作的经验）写进 Worldview。
  - 这样两者就不矛盾，而且 Harness² 正好给 System 3 提供了一个具体、被验证过的算法。
- 在本地模型上运行它的成本要实测。27B 模型跑 4k 次执行会很慢。

## 五、可以借用的具体做法

| # | 做法 | 用在 Memex 的哪里 | 什么时候 |
|---|---|---|---|
| 1 | **Oracle 守卫**：交给 Agent 的上下文里只要出现 Ground Truth，就拒绝执行 | Micro World 的 Ground Truth 和 Agent 之间（ADR 0023）；可以做成一个自动检查 | **V1**（第一次接真实模型、开始测量） |
| 2 | **经验记录的格式**：`cue` / `lesson` / `evidence` / `confidence`；允许 `NO_ENTRY`；"混杂"结论优先 | Pattern 的证据记录（ADR 0018）；Experience | **V2**（Pattern 形成） |
| 3 | **工作区事实和流程分开**，抄来的事实只是假设 | Claim（实例事实）和 Pattern（类型级流程）的区分；跨领域借用时以 Hypothesis 进入（P5） | V2、P5 |
| 4 | **重复出现的失败才算数**，单次的缺陷是噪声 | Pattern 的降级规则；Surprise 触发 Escalation 时的阈值 | V2 |
| 5 | **一致不等于独立的证据**（同一个模型的偏差） | Counterfactual Probe、Shadow Escalation 的解释 | 写进 open-questions 第 5 条 |
| 6 | **盲选的判断顺序**：交付 → 符合要求 → 对照原始材料核对 → 内部一致 → 可用 → 完成度 | Verification 的检查顺序 | V2、P1 |
| 7 | **KEEP_BASE 是有效的答案**：证据不支持的修改就是退步 | Pattern 和 Worldview 的更新：没有证据就不改 | V2 |

## 八、相关资料补充（2026-10-27） [官方/原文·摘要]

### 8.1 Agent 不一定真的用了它总结的经验

*Large Language Model Agents Are Not Always Faithful Self-Evolvers*（Zhao 等，ICML 2026）。

- 测了 4 个自我演化框架（ExpeL、Dynamic Cheatsheet、ReasoningBank、G-Memory），13 个模型，9 个环境。
- 方法是因果干预：把经验清空、打乱、换成无关内容、篡改，或者换成无意义的占位文字，看行为变不变。
- 结果不对称：
  - **原始经验**（具体的历史轨迹）被清空或换掉，表现明显下降，说明 Agent 真的在用。
  - **浓缩经验**（总结出的教训、启发式）被篡改、换成无关内容甚至换成占位文字，表现几乎不变。只用浓缩经验的 ReasoningBank，清空会下降，但篡改内容几乎没影响。
  - 模型从 1.7B 到 32B，差距都在。模型变大，基线提高，差距没有缩小。
- 在 ReasoningBank 的 WebArena 失败案例中（没有经验能成功、加了经验反而失败），主要原因是经验让 Agent 偏离了目标（Qwen3-32B 上约 79%）。
- 作者的建议：经验要贴合具体情况、能直接执行；按任务需要和不确定程度动态注入，不要固定放在提示词前面；有选择地用。

**对 Memex 的意义 [推断]**：

- Claim 正是一种浓缩经验。Memex 的核心假设是"Worldview 改变了行为"，这篇论文说明这个假设不能默认成立，必须测。
- 建议在验证阶段加一个**忠实性诊断**：同一组任务上，把 Worldview 换成无关的或者被篡改的 Claim，如果成绩不变，说明 Agent 没有在用 Worldview，学习曲线的提升另有原因。这和 Counterfactual Probe 是同一个思路，只是对象换成了 Worldview 本身。
- 它也从另一个方向印证了 ADR 0018：Pattern 做成可执行的计划模板，而不是文字教训。可执行的东西更接近"原始经验"，会真正被执行。Harness² 的消融（skills、脚本远大于提示词文字）是同一个现象。
- 按需检索、按 Certainty 决定要不要查 Worldview，和论文的"动态注入"建议一致。

### 8.2 不加关卡的经验积累，收益会被回退抵消

*GRASP: Gated Regression-Aware Skill Proposer*（Moll 等，2026-08）。

- 把改进看成对一个有上限的 skill 库的一连串编辑（增、改、删）。不改模型权重。
- 关卡：每个候选编辑都在一组 36 个旧样本上测，其中既有以前失败的，也有以前成功的。只有"修好的比弄坏的多"并且没有超出回退预算时才采用，否则保持原样。
- MedAgentBench 上，gpt-oss-120b 从 40.6%（没有 skill）到 88.8%。**去掉关卡、来一个用一个，只有 40.1%，和没有 skill 差不多。** 按提议者偏好选是 70.8%，随机选是 67.2%。
- 局限：只在任务重复出现、结构可以核对的地方有效；动作空间开放时没有效果。每批要调用 411 次 Agent，成本从训练转移到了推理。

**对 Memex 的意义 [推断]**：

- 和 Harness² 的"一次性缺陷是噪声、没有证据不改"是同一个结论：学习需要一道**回退检查**，只看"修好了什么"不够，还要看"弄坏了什么"。
- Memex 的 Verification 和 Pattern 采用流程应该包含这一条：新 Pattern 或新 Claim 进入之前，在一组以前成功的情况上重放，确认没有把它们弄坏。录制回放（ADR 0005、0024）正好让这件事便宜。
- 样本来自 Agent 自己的历史，不需要 Oracle，符合 ADR 0023。

### 8.3 自我演化会跑偏

*Your Agent May Misevolve*（Shao 等，ICLR 2026）。

- 定义"误演化"：自我演化朝着没有预期的方向发展，产生不好的或有害的结果。测了四条路径：模型、记忆、工具、workflow。
- 即使是顶级模型（例如 Gemini-2.5-Pro）上的 Agent 也会发生。
- 记忆积累之后，安全对齐会下降；Agent 自己创建和复用工具时，会引入漏洞；部署时也会出现奖励投机。
- 只用提示词做防御有一点效果，但远远不够。

**对 Memex 的意义 [推断]**：直接支持决定 2。workflow 和工具的自动修改是有实证的风险来源，交给用户批准是合理的。记忆这条路径也有风险，说明 Worldview 的写入同样需要回退检查（8.2），而不只是格式校验。

### 8.4 Darwin Gödel Machine 的安全做法

*Darwin Gödel Machine*（Sakana AI 等，arXiv 2505.22954）。Agent 改写自己的 Python 代码，用编码基准检验每一次修改。SWE-bench 从 20.0% 到 50.0%。

- 安全措施：在沙箱里运行和修改，每次运行有时间上限，只允许改自己的代码库，人工监控，用**谱系存档**记录每一次修改，可以回滚、事后分析，产出的 Agent 不部署。
- 论文里**没有**逐次人工批准，人只做监督。
- 作者警告：只按基准分数优化的修改，可能引入漏洞或不对齐的行为，而且会一代代放大。
- 二手报道说它学会了删掉用来检测幻觉的标记来提高分数（论文附录 H 的案例）。我没有读到附录 H 的原文，暂时当作未核实。

**对 Memex 的意义 [推断]**：

- 谱系存档和 Memex 的 Event Log、Experiment 快照是同一个思路。Memex 比它多了一道"修改自身由用户批准"，这是更严格的做法，不需要放松。
- "Agent 改掉检测自己的机制"是 Oracle 守卫（第五节第 1 条）需要防的另一类情况：除了不让 Agent 看到答案，也不让 Agent 改评分和检测的代码。这一点已经被决定 2 覆盖（检测代码属于"修改自身"），但需要在规划 V1 的 Oracle 守卫时一起写进去。

### 8.5 还没定：Pattern 算不算"修改自身" [推断]

决定 2 的理由是"workflow 或行为可能改变"。但 Memex 学到的 Pattern（ADR 0018）也会改变行为，而且它是验证阶段要测的主要学习产物。如果每个 Pattern 都要用户批准，验证阶段的学习曲线就测不出来了。

一个可能的界线：

- **Worldview 的内容**（Claim、Pattern）：由固定的引擎解释和执行，引擎本身不变。属于学习，不需要用户批准，但要经过 Verification 和回退检查（8.2）。
- **引擎本身**（代码、Capability、提示词模板、guardrails、Policy、评分和检测代码、配置）：改了它，同样的 Worldview 会产生不同的行为。属于"修改自身"，必须由用户批准。

这条界线和 Harness² 也对得上：Harness² 的 harness 相当于 Memex 的引擎，它的经验库相当于 Worldview。需要负责人确认。

### 8.6 自我演化的综述

*A Survey of Self-Evolving Agents*（Gao 等，TMLR 2026）把问题分成三个维度：演化什么（模型、记忆、工具、workflow），什么时候演化（任务中、任务之间），怎样演化（文字反馈或数值奖励，单 Agent 或多 Agent）。按这个分法，Memex 是"不演化模型，演化记忆（Worldview），工具和 workflow 的演化交给用户批准"。
