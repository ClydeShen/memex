## 需要决定

1. **Micro World 对 Agent 隐藏什么。**（何时决定：M2 实现真实的世界生成器之前。做法：做成生成器的配置项，例如 `visibility: {state, rules, actionEffects}`，这样就不是一次性的决策；M0 先用最简单的世界。） 有两个选项：只隐藏世界状态；或者连因果规则和动作效果也一起隐藏，让 Agent 自己摸索。后者更贴近"建立世界观"的目标，但也更难。如果规则是公开的，T1–T3 就很接近规划问题，B-sym 可能占优。
2. **流程精简。**（何时决定：进入正式阶段时，见 ADR 0012。） 提议：保留可复现、实验隔离、对照组、学习曲线和基本统计（均值、置信区间）；简化 release 数据集的保密流程、72 小时稳定性测试，以及 Alpha/Beta/RC/V1 的正式关卡。
3. **个人数据如何删除。**（何时决定：M3 接入 World 0 之前，或者 Memex 分发给他人使用之前，以先到者为准。见 docs/security-and-data.md D8。） Event Log 只追加、不修改，但个人数据可能需要真正删除。常见做法有两种：一是把个人数据放在日志之外单独存储，事件中只保存引用（forgettable payload）；二是每个人一把加密密钥，删除数据时销毁密钥（crypto-shredding）。有观点认为只销毁密钥不一定满足 GDPR 的删除要求。目前只使用合成数据，暂时不受影响。注意：Decay 是认知层面的"不再相信"，不等于删除数据。
